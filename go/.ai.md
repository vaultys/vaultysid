# AI Contribution Guide for VaultysID Go Implementation

## Overview

This guide helps AI assistants understand and contribute to the VaultysID Go implementation. VaultysID is a decentralized identity management system supporting multiple identity types (machine, person, organization) with advanced cryptographic capabilities.

Go implementation should follow carefully the reference implementation in typescript that can be found under ../typescript and contribute to interops tests under ../interops

## Key Concepts

### 1. Identity Types
- **Machine** (0x00): For servers, IoT devices, applications
- **Person** (0x01): For individual users
- **Organization** (0x02): For companies, groups
- **FIDO2** (0x03): Hardware-based authentication
- **FIDO2PRF** (0x04): FIDO2 with PRF extension

### 2. Core Components

#### VaultysID (`pkg/vaultysid/`)
The main identity structure containing:
- Type (identity type)
- KeyManager (handles cryptographic operations)
- Certificate (an opaque `[]byte`, not an X.509 certificate — nothing here parses or validates X.509)

Key methods:
- `GenerateMachine()`, `GeneratePerson()`, `GenerateOrganization()` - Create new Ed25519 identities
- `GeneratePersonAlg(alg string)` and siblings - Create with a chosen algorithm (`"ed25519"` or `"dilithium"`)
- `FromEntropy(entropy []byte, idType)` - Create from 32-byte entropy
- `FromSecret(secret []byte)` - Restore from secret
- `FromID(id []byte, cert []byte)` - Create public-only identity
- `Sign(data []byte)` - Sign data
- `Verify(data, signature []byte) error` - Verify a signature
- `DID()` - Get Decentralized Identifier

Combined classical + post-quantum ("dilithium_ed25519") identities are not implemented: requesting that algorithm returns an error (`vaultysid.go`).

#### IDManager (`pkg/idmanager/`)
Manages persistent storage of identities, contacts, and apps:
- Store interface for different backends (memory, file)
- Contact management
- App/service registration
- Metadata storage (name, email, phone)
- Backup/restore functionality

The `IdentityManager` interface in `types.go` predates the current `*Manager` method signatures and no longer matches them (e.g. `SaveApp`, `VerifyFile`); don't use it as a reference for `Manager`'s actual API — read `manager.go` directly.

#### KeyManager (`pkg/keymanager/`)
Handles cryptographic operations:
- Ed25519 for signing/verification, X25519 for encryption/key exchange (`Ed25519Manager`)
- ML-DSA-87 (FIPS 204, formerly Dilithium5) for post-quantum signing, X25519 for encryption/key exchange (`DilithiumManager`)
- FIDO2/WebAuthn signature verification only, no signing (`FIDO2Manager`)

`keymanager.KeyManager` and `vaultysid.KeyManager` (`pkg/vaultysid/types.go`) are two separately declared interfaces with identical method sets. Go does not link them nominally, so a method added to one won't surface as a compile error in the other — check both when changing the contract.

### 3. Data Formats

#### Identity ID Format
```
[type_byte][keymanager_data]
```
- First byte: identity type
- Remaining: serialized key manager data (msgpack)

#### Secret Format
```
[type_byte][private_key_data]
```
- First byte: identity type
- Remaining: private key material

#### DID Format
```
did:vaultys:[40_hex_chars]
```
- 40 hex chars = first 40 chars of hex(type_byte + SHA224(keymanager_id))

```go
    // Implementation
    return nil

// In init()
rootCmd.AddCommand(newCmd)
```

2. **New VaultysID Method**
```go
// In pkg/vaultysid/vaultysid.go
func (v *VaultysID) NewMethod() error {
    // Ensure proper state
    if !v.IsPrivate() {
        return fmt.Errorf("operation requires private key")
    }
    
    // Delegate to KeyManager
    return v.KeyManager.SomeOperation()
}
```

3. **New Storage Feature**
```go
// In pkg/idmanager/manager.go
func (m *Manager) NewFeature() error {
    m.mu.Lock()
    defer m.mu.Unlock()
    
    // Access store
    data := m.store.Get("key")
    
    // Modify and save
    m.store.Set("key", newData)
    return m.store.Save()
}
```

### Testing Guidelines

1. **Unit Tests** - Test individual functions
```go
func TestFunctionName(t *testing.T) {
    // Arrange
    input := setupTestData()
    
    // Act
    result, err := FunctionUnderTest(input)
    
    // Assert
    assert.NoError(t, err)
    assert.Equal(t, expected, result)
}
```

2. **Integration Tests** - Test complete workflows
```go
func TestCompleteWorkflow(t *testing.T) {
    // Generate identity
    vid, err := vaultysid.GeneratePerson()
    require.NoError(t, err)

    // Use identity
    signature, err := vid.Sign(data)
    require.NoError(t, err)

    // Verify
    err = vid.Verify(data, signature)
    assert.NoError(t, err)
}
```

`Verify` returns an `error`, not a `bool` — assert on `err`, not on a returned boolean.

3. **Compatibility Tests** - Ensure TypeScript compatibility
- Located in `test/compatibility/`
- Use test vectors from TypeScript implementation

### API Patterns

1. **Error Handling**
```go
if err != nil {
    return fmt.Errorf("context: %w", err)
}
```

2. **Method Signatures**
- Getters: `func (v *VaultysID) Property() type`
- Actions: `func (v *VaultysID) DoSomething(params) error`
- Creators: `func NewThing() (*Thing, error)`

3. **Thread Safety**
```go
type SafeStruct struct {
    mu   sync.RWMutex
    data map[string]interface{}
}

func (s *SafeStruct) Read() interface{} {
    s.mu.RLock()
    defer s.mu.RUnlock()
    return s.data["key"]
}

func (s *SafeStruct) Write(value interface{}) {
    s.mu.Lock()
    defer s.mu.Unlock()
    s.data["key"] = value
}
```

## Important Considerations

### 1. Compatibility
- Must maintain compatibility with TypeScript implementation
- Use msgpack for serialization (matches TypeScript)
- Test vectors should pass across implementations

### 2. Security
- Never log or expose private keys
- Use constant-time comparisons for sensitive data
- Validate all inputs before processing
- Use crypto/rand for randomness

### 3. Performance
- Profile before optimizing
- Use sync.Pool for frequently allocated objects
- Minimize allocations in hot paths
- Cache expensive computations

### 4. Code Style
- Follow Go conventions (gofmt, golint)
- Use meaningful variable names
- Add comments for exported functions
- Keep functions focused and small

## Common Pitfalls

1. **Method Returns**
- `NewManager()` returns single value, not error
- `GetSecret()` returns ([]byte, error)
- `ID()` returns bytes, use `ToString()` for string

2. **Encoding**
- Default encoding is "hex" for CLI
- Use base64.StdEncoding for base64
- FromIDString accepts encoding parameter

3. **Store Operations**
- FileStore needs explicit Save() calls
- MemoryStore doesn't persist
- Always check if store file exists before loading

4. **Identity Types**
- FIDO2 identities require special handling
- Not all operations available for all types
- Public-only identities can't sign

5. **Exported error values**
- `pkg/vaultysid/errors.go` declares errors such as `ErrNoPrivateKey` and `ErrInvalidSignature` that no function in the package currently returns — functions use inline `fmt.Errorf` instead. Don't assume `errors.Is(err, vaultysid.ErrX)` will match; check what the call you're wrapping actually returns.
- `ErrFIDO2NotImplemented` describes a state that no longer holds: FIDO2 verification is implemented in `pkg/keymanager/fido2.go`. Only signing is unavailable.
