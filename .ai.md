# VaultysID - AI Contributor Guide

## Project Overview

VaultysID is a decentralized identity framework that provides cryptographic identity management with support for multiple signature schemes and key management systems. The project implements a handcheck protocol for secure identity verification and authentication.

### Key Features
- **Decentralized Identity (DID)**: Self-sovereign identity management without central authorities
- **Multiple Cryptographic Schemes**: Ed25519, X25519, Dilithium (post-quantum), and hybrid schemes
- **Hardware Security Support**: FIDO2/WebAuthn integration for hardware-backed keys
- **Cross-Platform**: TypeScript implementation for Node.js and browsers, with Rust implementation for native performance
- **Handcheck Protocol**: Challenge-response authentication protocol for secure identity verification

## Architecture

### Core Components

#### 1. VaultysId Class (`typescript/src/VaultysId.ts`)
- Main identity container class
- Manages identity types: Machine (0), Person (1), Organization (2), FIDO2 (3), FIDO2PRF (4)
- Handles signing, verification, and identity operations
- Serialization/deserialization of identities

#### 2. Key Managers (`typescript/src/KeyManager/`)
- **AbstractKeyManager**: Base interface for all key managers
- **Ed25519Manager**: Standard Ed25519/X25519 cryptography
- **DilithiumManager**: Post-quantum resistant signatures
- **HybridManager**: Combined Ed25519 + Dilithium for quantum resistance
- **Fido2Manager/Fido2PRFManager**: Hardware security key support via WebAuthn
- **DeprecatedKeyManager**: Backward compatibility with v0 format
- **CypherManager**: Base class for encryption operations

#### 3. Challenger (`typescript/src/Challenger.ts`)
- Implements the handcheck protocol
- Two-party mutual authentication
- Challenge-response flow with nonces and signatures
- Metadata exchange during authentication

#### 4. IdManager (`typescript/src/IdManager.ts`)
- Higher-level identity management
- Persistent storage integration
- Protocol and service key derivation
- Metadata management

#### 5. Crypto Channel (`typescript/src/cryptoChannel.ts`)
- Secure communication channel
- End-to-end encryption using X25519
- Message authentication and integrity

## Cryptographic Design

### Identity Format
Each identity consists of:
1. **Type byte**: Indicates identity type (Machine/Person/Organization/FIDO2)
2. **Key material**: Public keys for signing and encryption
3. **Optional certificate**: For certified identities

### Key Derivation
- BIP32-Ed25519 for hierarchical key derivation
- Protocol/service-specific key derivation paths
- Proof keys for key rotation scenarios

### Signature Schemes
- **Ed25519**: Default signature scheme (fast, secure)
- **Dilithium3**: Post-quantum signatures (NIST PQC winner)
- **Hybrid**: Ed25519 + Dilithium for transitional quantum resistance

### Encryption
- **X25519**: Elliptic curve Diffie-Hellman
- **DHIES**: Diffie-Hellman Integrated Encryption Scheme
- **Saltpack**: Optional message format for encrypted/signed data

## Important Implementation Details

### Buffer Handling
- Always use `Buffer.from()` for creating buffers
- Handle both Node.js Buffer and browser Uint8Array
- Support for "stringified" buffer format in JSON

### Async Operations
- Key generation is async (especially for post-quantum)
- WebAuthn operations are inherently async
- File operations in Node.js use async APIs

### Cross-Platform Considerations
- Different crypto providers for Node.js vs browsers
- WebAuthn only available in secure browser contexts
- File system access differs between environments

### Security Considerations
- Never expose private keys in logs or errors
- Use constant-time comparisons for MAC verification
- Zeroize sensitive memory (especially in Rust implementation)
- Validate all inputs before cryptographic operations

## API Patterns

### Creating an Identity
```typescript
// Generate new identity
const machineId = await VaultysId.generateMachine();
const personId = await VaultysId.generatePerson();

// From existing keys
const id = VaultysId.fromId(idBuffer);
```

### Signing and Verification
```typescript
// Sign data
const signature = await id.sign(data);

// Verify signature
const isValid = id.verify(data, signature);

// Sign challenge (handcheck protocol)
const signed = await id.signChallenge(challenge);
```

### Challenge Protocol
```typescript
const challenger = new Challenger(vaultysId);
await challenger.init(protocol, service);
const step1 = challenger.step1();
// Exchange with peer...
const step2 = challenger.step2(peerStep1);
```

## Common Pitfalls

1. **Buffer vs Uint8Array**: Always normalize to Buffer in TypeScript
2. **Async key generation**: Don't forget await for PQ key generation
3. **Platform detection**: Check for WebAuthn availability before use
4. **Path resolution**: Use proper project root paths
5. **Version compatibility**: Check identity version before operations
